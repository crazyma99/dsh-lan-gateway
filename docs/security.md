# dsh-lan-gateway 安全模型

## 威胁模型

网关把「任意局域网设备 → dsh WebUI」这条路径从完全禁止变成**显式开启、逐请求认证**。
攻击面：同一网段内（或通过路由可达该端口）的任意设备，包括恶意设备与被入侵设备。
网关不是 VPN 的替代品——它是在局域网信任边界内提供最小可用暴露。

## 设计决策

| 层 | 决策 | 理由 |
|---|---|---|
| 主服务绑定 | `dsh web` 保持 `127.0.0.1:3080` 不变 | 网关是唯一暴露面，无旁路 |
| 加密 | 仅 HTTPS/WSS（`node:https`），无明文 HTTP | 密码与流量不落地在明文网络上 |
| 证书 | 自签 ECDSA P-256（10 年，7 天内到期自动重生成），指纹在设置页展示；可换自定义证书 | 零依赖、可校验（指纹防中间人），生产可换 CA 证书 |
| 认证 | 登录页 + HMAC 会话 Cookie（`HttpOnly; Secure; SameSite=Strict`，7 天滑动续期）；Basic 兼容非浏览器客户端；恒定时间比较（SHA-256 + `timingSafeEqual`） | 浏览器不再弹原生 Basic 提示；Cookie 签名密钥派生自密码，改密码即失效全部会话；恒定时间避免时序侧信道 |
| 密码存储 | `role('secret')` 设置字段 | 任何 wire 表面脱敏；只存宿主机本地 settings 文档 |
| 授权 | 可选 IP 白名单（CIDR） | 进一步收窄来源网段 |
| Host/Origin 重写 | 转发到 loopback 并重写为 `127.0.0.1:<port>` | 后端 `/api` 信任围栏（DNS-rebinding/跨站防护）原样生效 |
| 特权面隔离 | 状态 RPC 仅 `authority: 'loopback'`；`settings.*`/`credentials.*` 等对 LAN 客户端依旧 403 | 局域网设备只能使用 UI，不能改配置、读密钥 |
| 默认关闭 | `enabled: false`，密码为空时拒绝开启（`validate` 在写入时拦截） | 无意识暴露不可能 |
| 失败关闭 | 端口占用/证书错误 → 状态 `error`，绝不降级为明文 | 宁可不服务，也不降低安全姿态 |
| 生命周期 | 禁用/插件卸载时 `server.close()` + 销毁所有 socket | 无残留监听 |

## 剩余风险与缓解

1. **登录失败限流**：按来源 IP 在 10 分钟窗口内超过 5 次失败即拒绝（429 语义并入错误页）。缓解暴力破解。
2. **自签证书信任环**：首次信任依赖用户核对指纹（TOFU）。攻击者若在首次信任前
   完成中间人，理论上可替换证书。缓解：设置页展示完整指纹；生产环境使用 CA 签发证书。
3. **无审计日志**：V1 不记录访问日志。缓解：V2 计划连接审计。
4. **宿主机回环即信任**：网关以 loopback 身份调用后端，后端无法区分「本机用户」
   与「网关转发的局域网用户」。这是重写方案的本质取舍：局域网用户在**会话能力**
   上等同于本机用户（能启动 session、跑 bash），但配置/凭据面仍被特权 RPC 钉在
   loopback。**开启网关 = 把会话执行能力授予所有能通过认证的设备**，请用强密码。
5. **端口暴露于防火墙**：网关监听 `0.0.0.0`。若宿主机有防火墙，建议仅放行所需网段
   （与 IP 白名单形成双保险）。

## 不承诺

- 不提供多用户/多口令（单一 username/password）。
- 不做端到端加密到浏览器之外的场景（会话内容本身是明文 HTML/JSON，由 TLS 保护）。
- 不修改 dsh 上游的任何信任与特权策略。
